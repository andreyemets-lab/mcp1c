# mcp1c — MCP-сервер для 1С:Підприємство 8.3

Розширення конфігурації, яке відкриває дані будь-якої бази 1С/BAS для AI-клієнтів (Claude, ChatGPT, Cursor, локальні моделі) за протоколом [Model Context Protocol](https://modelcontextprotocol.io/specification/2026-07-28).

- **Лише читання.** Жодних записів, проведення чи довільного коду.
- **Доступ за токеном з терміном дії** і миттєвим відкликанням; OAuth 2.1 для веб-конекторів — на етапі 3.
- **Права за профілем клієнта:** об'єкти, поля, рядки, маскування, ліміти обсягу.
- **Універсальність:** без запозичених об'єктів і без залежності від БСП; знання про дані береться з метаданих під час виконання.

Повне технічне завдання: [docs/TZ.md](docs/TZ.md).

## Етапи

| Етап | Зміст | Стан |
| --- | --- | --- |
| 0. Прототип | Протокол MCP 2026-07-28 і сумісність, PAT-токени, інструменти метаданих; перевірка платформних ризиків | код готовий, потрібна перевірка на базах |
| 1. Ядро і безпечне читання | Клієнти й профілі доступу, глобальні заборони, 9 інструментів читання, аудит у регістрі, адмін-форми | — |
| 2. Тонке керування | Маскування, рядкові обмеження з параметрами, ліміти, користувацькі інструменти, ресурси, промпти | — |
| 3. Інтеграції | OAuth 2.1, модель A (JWT платформи), звіти СКД, повнотекстовий пошук | — |

## Етап 0: що вміє прототип

- MCP-ендпоінт на HTTP-сервісі `mcp1c_Сервер` (`/hs/mcp1c`): редакція **2026-07-28** (`server/discover`, заголовки `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, коди `-32020`/`-32022`) і сумісність із клієнтами **2025-11-25 / 2025-06-18** (`initialize`, `ping`).
- Персональні токени `mcp1c_<id>_<secret>` з терміном дії; у базі лише SHA-256 секрету; відкликання діє з наступного запиту. Токен приймається з `Authorization: Bearer` або `X-MCP-Authorization: Bearer`, у рядку запиту — відхиляється.
- Захист: перевірка `Origin`, ліміт тіла, `Content-Type`, прив'язка до рядка з'єднання ІБ (копія бази відповідає 503).
- Інструменти лише метаданих — дані ІБ ще не читаються: `get_context`, `list_objects`, `describe_object`.
- Журнал реєстрації: події `MCP.Вызов`, `MCP.Токены`, `MCP.Безопасность`, `MCP.Настройки`, `MCP.Ошибка`; секрети не пишуться.

## Встановлення прототипу

### 1. Розширення

1. Імпортуйте `exts/mcp1c` у робочу область EDT. У `DT-INF/PROJECT.PMF` замініть `Base-Project: configuration` на ім'я вашого проєкту конфігурації (або вкажіть базовий проєкт у властивостях проєкту). `Runtime-Version: 8.3.23` змініть на версію платформи вашого сервера, якщо вона старша.
2. Завантажте розширення в ІБ з EDT або експортуйте `.cfe` і підключіть його в «Розширеннях конфігурації».
3. Вимкніть **«Безпечний режим»** і **«Захист від небезпечних дій»** для розширення: потрібні привілейовані модулі.

Режим сумісності розширення — 8.3.10, тож воно має ставитися на конфігурації з режимом сумісності 8.3.10 і вище. Конфігурації з режимом 8.2.x — один із ризиків, які перевіряє прототип.

### 2. Технічний користувач і публікація

1. Створіть користувача ІБ, наприклад `mcp1c_gateway`: автентифікація 1С, складний пароль, без інтерактивних ролей, роль `mcp1c_Сервис`. У конфігураціях на БСП створюйте його штатно через «Користувачі» й додайте роль у профіль групи доступу, інакше БСП може перезаписати ролі.
2. Зробіть **окрему** публікацію лише для MCP: без клієнтських застосунків і OData, HTTP-сервіси — тільки `mcp1c_Сервер`. Облікові дані технічного користувача — у рядку з'єднання `default.vrd`:

```xml
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       base="/erp-mcp"
       ib="Srvr=&quot;app01&quot;;Ref=&quot;erp&quot;;Usr=&quot;mcp1c_gateway&quot;;Pwd=&quot;***&quot;;"
       enable="false">
  <standardOdata enable="false"/>
  <httpServices publishByDefault="false" publishExtensionsByDefault="false">
    <service name="mcp1c_Сервер" rootUrl="mcp1c" enable="true" reuseSessions="autouse"
             sessionMaxAge="20" poolSize="10" poolTimeout="5"/>
  </httpServices>
</point>
```

Ендпоінт: `http://<веб-сервер>/erp-mcp/hs/mcp1c`. Ззовні — лише через реверс-проксі з TLS (приклад nginx — ТЗ, п. 11.2).

### 3. Увімкнення сервера і токен

Виконайте в контексті сервера будь-якою консоллю коду, під користувачем із правом «Адміністрування» або роллю `mcp1c_Администратор`:

```bsl
mcp1c_Администрирование.ВключитьСервер("https://mcp.company.ua/mcp");
Выпуск = mcp1c_Администрирование.ВыпуститьТокен("Claude Code - Андрій", 30);
Сообщить(Выпуск.Токен); // показується один раз, у базі зберігається лише хеш
```

Перший автентифікований запит прив'язує сервер до розташування бази (File, Srvr, Ref з рядка з'єднання публікації). Копія бази в іншій ІБ відповідатиме 503, доки не виконати `ПодтвердитьПереносИнформационнойБазы()`; за замовчуванням це відкликає всі токени.

Інші методи модуля: `ОтозватьТокен`, `СписокТокенов`, `ОписаниеНастроек`, `УстановитьРазрешенныеИсточники`, `УстановитьИнструкции`, `ВыключитьСервер`.

### 4. Підключення клієнтів

Claude Code:

```bash
claude mcp add --transport http onec https://mcp.company.ua/mcp \
  --header "Authorization: Bearer mcp1c_XXXXXXXXXXXX_YYYY"
```

Cursor (`~/.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "onec": {
      "url": "https://mcp.company.ua/mcp",
      "headers": { "Authorization": "Bearer mcp1c_XXXXXXXXXXXX_YYYY" }
    }
  }
}
```

Клієнти лише зі stdio — через міст [mcp-remote](https://www.npmjs.com/package/mcp-remote): `npx -y mcp-remote <url> --header "Authorization:${MCP1C_AUTH}"`.

Якщо веб-розширення 1С перехоплює `Authorization: Bearer` і відповідає 401 ще до коду сервісу, передавайте токен у `X-MCP-Authorization: Bearer ...` (або переносьте заголовок на проксі).

### 5. Перевірка

```bash
python tools/mcp_smoke_test.py --url http://<веб-сервер>/erp-mcp/hs/mcp1c --token mcp1c_...
# варіант із запасним заголовком:
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --auth-header X-MCP-Authorization
```

Скрипт проходить 26 перевірок (токен, Origin, коди помилок, `server/discover`, інструменти, курсор, сценарій клієнта 2025-11-25) і завершується кодом 1, якщо щось не так. Потрібен лише Python 3.8+.

## Що має підтвердити прототип

- [ ] `Authorization: Bearer` доходить до HTTP-сервісу в публікації без `accessTokenAuthentication`; якщо ні — працює `X-MCP-Authorization`.
- [ ] Розширення застосовується до трьох конфігурацій з різним режимом сумісності (зафіксувати, які саме).
- [ ] IP клієнта приходить від проксі (`X-Real-IP`) і видно в журналі реєстрації.
- [ ] Claude Code і Cursor підключаються й викликають інструменти.
- [ ] Копія бази в іншій ІБ відповідає 503, доки перенос не підтверджено.
- [ ] `tools/mcp_smoke_test.py` проходить на всіх трьох базах.

## Перевірки без платформи

```bash
python tools/check_metadata.py exts/mcp1c
cd tools/bsl-syntax && npm ci && node check.mjs ../../exts/mcp1c/src
```

Ті самі перевірки запускає CI на кожен PR. Вони ловлять зламаний XML, неузгоджені метадані, виклики неіснуючих або неекспортних методів і синтаксичні помилки BSL; компіляцію в EDT вони не замінюють.
