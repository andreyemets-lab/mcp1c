# mcp1c — MCP-сервер для 1С:Підприємство 8.3

Розширення конфігурації, яке відкриває дані будь-якої бази 1С/BAS для AI-клієнтів (Claude, ChatGPT, Cursor, локальні моделі) за протоколом [Model Context Protocol](https://modelcontextprotocol.io/specification/2026-07-28).

- **Лише читання.** Жодних записів, проведення чи довільного коду: запити будує сервер з канонічних імен метаданих, значення з аргументів ідуть тільки параметрами.
- **Доступ за токеном з терміном дії** і миттєвим відкликанням; OAuth 2.1 для веб-конекторів — на етапі 3.
- **Права за профілем клієнта:** інструменти, об'єкти, поля й маски, обмеження рядків зі значеннями клієнта, режим «тільки агрегати», ліміти обсягу; усе, що не дозволено, заборонено.
- **Універсальність:** без запозичених об'єктів і без залежності від БСП; знання про дані береться з метаданих під час виконання.

Повне технічне завдання: [docs/TZ.md](docs/TZ.md).

| Етап | Зміст | Стан |

| 1. Ядро і безпечне читання | Клієнти й профілі доступу, глобальні заборони, 9 інструментів читання, ліміти, журнал викликів | перевірено на BAS ERP 2.5.5; лишаються ще дві конфігурації |
| 2. Тонке керування | Маскування, режим агрегатів, обмеження рядків з параметрами, автоблокування, ресурси, промпти й глосарій, користувацькі інструменти, пісочниця, аналіз ризиків, вивантаження й завантаження налаштувань | перевірено на BAS ERP 2.5.5; лишаються ще дві конфігурації |

## Що вміє сервер

### Протокол

- MCP-ендпоінт на HTTP-сервісі `mcp1c_Сервер` (`/hs/mcp1c`): редакція **2026-07-28** (`server/discover`, заголовки `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, коди `-32020`/`-32022`) і сумісність із клієнтами **2025-11-25 / 2025-06-18** (`initialize`, `ping`).
- Методи: `tools/list`, `tools/call`, `resources/list`, `resources/templates/list`, `resources/read`, `prompts/list`, `prompts/get`. Списки й ресурси мають підказки кешування `ttlMs` і `cacheScope: private` (склад залежить від профілю клієнта).
- Без сесій: кожен запит самодостатній, тож сервер працює з пулом сеансів веб-публікації.

### Інструменти

| Інструмент | Що повертає |
| --- | --- |
| `get_context` | конфігурація, платформа, час і часовий пояс сервера, клієнт, профіль, ліміти |
| `list_objects` | доступні об'єкти метаданих з фільтром за видами й пошуком |
| `describe_object` | реквізити з типами, табличні частини, виміри й ресурси, поля пошуку, придатні інструменти |
| `find_objects` | пошук елементів і документів за рядком у полях пошуку |
| `get_object` | картка об'єкта за посиланням з табличними частинами |
| `query_records` | вибірка з довідника, документа, табличної частини або регістра: фільтри, період, групування, агрегати, сортування |
| `get_balances` | залишки регістра накопичення або бухгалтерії на дату |
| `get_turnovers` | обороти за період, з розбивкою за періодами і залишками |
| `get_slice` | зріз останніх або перших записів періодичного регістра відомостей |

Після вбудованих — **користувацькі інструменти** адміністратора (довідник `mcp1c_ПользовательскиеИнструменты`, ТЗ п. 5.5), за іменем і лише для призначених профілів:

- вид «Запрос» — текст запиту з параметрами `&Имя`; «Компоновка данных» — схема СКД у XML (зовнішні функції заборонені); «Метод модуля» — експортна функція серверного загального модуля `Функция(Параметры, Контекст)`, виконується в транзакції, яка завжди скасовується;
- параметри з типами, обов'язковістю, значенням за замовчуванням, переліком допустимих значень і ознакою списку дають `inputSchema`; параметр, прив'язаний до параметра профілю, моделі не видно — значення бере сервер із клієнта доступу;
- при записі текст запиту розбирається `СхемаЗапроса`, схема й модуль перевіряються; адміністратор бачить попередження про джерела поза профілями й обмеження рядків, яких запит не застосовує; зміна інструмента — подія безпеки.

Посилання повертаються як `{"type", "ref", "presentation"}` і так само передаються у фільтри. Дати — місцевий час сервера в ISO 8601 без часового поясу; дата без часу у верхній межі означає кінець дня. Великі вибірки — сторінками з курсором `next_cursor`, підписаним HMAC і прив'язаним до клієнта й аргументів.

### Ресурси, промпти, глосарій

- Ресурси: `onec://context` (те саме, що `get_context`), `onec://glossary`, шаблони `onec://metadata/{object}` (`describe_object`) і `onec://object/{object}/{ref}` (`get_object`). Ресурс доступний, якщо профіль дозволяє інструмент, що дає його вміст, і проходить ті самі перевірки політики, маски й ліміти. Кирилиця в URI — у кодуванні URL, у заголовку `Mcp-Name` — base64.
- Промпти — довідник `mcp1c_Промпты`: ім'я, опис, текст з `{{аргумент}}` і `{{today}}`, аргументи, профілі (без профілів — усім клієнтам з профілем).
- Глосарій бази (`mcp1c_Администрирование.УстановитьГлоссарий`) — терміни й визначення для інструкцій моделі, `get_context` і `onec://glossary`.

### Доступ

- **Клієнт доступу** (`mcp1c_КлиентыДоступа`) — кому видано токени: профіль, користувач ІБ, дозволені IP і `Origin`, вікно часу, власні ліміти (лише менші за профіль), блокування.
- **Профіль доступу** (`mcp1c_ПрофилиДоступа`):
  - *Инструменты* — дозволені інструменти; порожньо — усі 9 інструментів читання;
  - *Объекты* — повне ім'я або шаблон (`Документ.*`, `*`), режим «Чтение», «Только агрегаты» або «Запрещено», політика полів («Все кроме запрещенных» або «Только разрешенные»), обов'язковий фільтр за періодом, мінімальний розмір групи;
  - *Поля* — дозволи, заборони й маски полів і табличних частин (`Товары`, `Товары.Цена`);
  - *ОграниченияСтрок* — рядки лише з певними значеннями поля: «Равно», «НеРавно», «ВИерархии»; значення — JSON у форматі аргументів, наприклад `{"type": "Справочник.Организации", "ref": "<uuid>"}` або масив таких значень, або параметр профілю;
  - *Параметры* — параметри профілю (ім'я, типи), значення яких задає кожен клієнт (ТЧ *ЗначенияПараметров*): наприклад, `РазрешенныеОрганизации` — одне значення дає `=`, кілька — `В`; неописаний параметр, відсутнє чи невідповідного типу значення закривають об'єкт;
  - ліміти: рядків за виклик, викликів за хвилину, рядків за добу, довжина періоду, розмір відповіді, глибина розіменування.
- **Маски** (ТЗ п. 7.4): повна `***`, часткова `***1234`, хеш `h:` + 12 символів SHA-256 із сіллю профілю, округлення до кроку. Масковане поле видно (у `describe_object` — `mask`), але воно не бере участі у фільтрах, сортуванні, групуванні й розіменуванні; з агрегатів — лише `count` і `count_distinct` (для округлення — і сума).
- **Режим «тільки агрегати»**: лише `query_records` з `group_by` і `aggregates`; групи, менші за мінімальний розмір (типово 5), відкидаються `ИМЕЮЩИЕ КОЛИЧЕСТВО(*) >= k`; окремі записи, `min`/`max`, залишки й обороти (у віртуальних таблицях записи вже згорнуті), розіменування й представлення закриті.
- **Глобальні заборони** в налаштуваннях сервера: шаблони об'єктів і полів (паролі, токени, службові об'єкти розширення), які не відкриє жоден профіль.
- **Права користувача ІБ**, якщо його вказано в клієнті, — верхня межа: об'єкти, які він не може читати, недоступні й клієнту.
- Прихований об'єкт чи поле не відрізняється від відсутнього; посилання на об'єкт, представлення якого клієнту недоступне, показується як `<приховано>`.

### Захист і журнал

- Токени `mcp1c_<id>_<secret>`: у базі лише SHA-256 секрету, відкликання діє з наступного запиту. Токен приймається з `Authorization: Bearer` або `X-MCP-Authorization: Bearer`, у рядку запиту — відхиляється.
- Перевірка `Origin`, ліміт тіла, `Content-Type`, прив'язка до розташування ІБ (копія бази відповідає 503).
- Блокування IP після серії невдалих автентифікацій (типово 10 за 5 хвилин, на 15 хвилин); перевищення частоти — 429 з `Retry-After`, добової квоти — помилка інструмента.
- Автоблокування клієнта після серії відмов політики (типово 30 за 10 хвилин, на 15 хвилин) — так виглядає перебір того, що профіль приховує; знімає адміністратор (`СнятьБлокировкуКлиента`).
- Тексти з даних очищаються від керуючих і невидимих символів Unicode; довгі рядки обрізаються.
- Журнал викликів `mcp1c_ЖурналВызовов`: клієнт, токен, IP, метод, інструмент, об'єкти, кількість рядків, розмір, результат, причина відмови. Події токенів, безпеки й налаштувань — у журналі реєстрації (`MCP.*`); секрети не пишуться.
- Записи журналу викликів, старші за 180 днів (`УстановитьСрокХраненияЖурнала`, 0 — не очищати), щодня о 03:00–05:00 видаляє регламентне завдання «Очистка журнала вызовов MCP», не довше пів години за запуск. Адміністратор журнал не змінює: у ролі `mcp1c_Администратор` немає права зміни, тож завдання виконується з правами користувача регламентних завдань (у кластері без вказаного користувача — з повними правами). У файловій базі регламентні завдання виконує відкритий клієнтський сеанс 1С.

### Адміністрування

Підсистема **«MCP-сервер»**:

| Команда | Де | Що робить |
| --- | --- | --- |
| Рабочее место MCP-сервера | підсистема, перший пункт | стан, публічна адреса, увімкнення й вимкнення, підтвердження перенесення бази; попередження (сервер вимкнено, не задано адресу, IP клієнта не надходить від проксі, токени спливають, профілі показують чутливі поля без маски — перевірка за командою); показники за добу й тиждень (виклики за результатами, рядки, обсяг, клієнти, середня, медіана, p95 і найдовша тривалість), топ інструментів і об'єктів, останні відмови, токени, що спливають, активні блокування зі зняттям. Аудитор бачить показники без налаштувань сервера |
| Выпустить токен MCP, Отозвать токен | форма клієнта, форма токена | токен показується один раз разом із фрагментами підключення |
| Песочница MCP | форма клієнта | виклик інструмента, ресурсу чи промпту від імені клієнта: точна відповідь моделі, застосовані правила профілю, попередження (блокування, вікно часу, токени, частота, квота); ліміти клієнта не витрачаються, у журнал викликів не пишеться, подія `MCP.Песочница` |
| Анализ рисков | форма профілю | чутливі поля без маски, клієнти із зовнішнім AI-провайдером, правило `*`, об'єкти без фільтра періоду, малий розмір групи, помилки обмежень, збільшені ліміти; пропонує замаскувати знайдені поля рекомендованими масками |
| Чувствительные поля MCP | підсистема | кандидати в чутливі поля за іменами, синонімами й типом значення (номер чи адреса — рядок, оплата праці — число): ІПН/РНОКПП, документи особи, адреси, телефони, e-mail, рахунки й картки, дата народження, оплата праці, контактна інформація |
| Выгрузить / Загрузить настройки MCP | підсистема | профілі, користувацькі інструменти, промпти, інструкції, глосарій і глобальні заборони в JSON (без токенів, клієнтів і секретів); завантаження — за іменами, одна транзакція, спершу перевірка без запису; елементи, що збігаються з базою, не перезаписуються («без змін») |

Те саме з коду: `mcp1c_Песочница.ВыполнитьМетод(Клиент, "tools/call", Параметры)`, `mcp1c_АнализДоступа.АнализРисков(Профиль)`, `ЧувствительныеПоля`, `ЗамаскироватьЧувствительныеПоля`, `ПрофильТолькоМетаданные()` (профіль лише зі структурою бази для першого підключення), `mcp1c_ОбменНастройками.Выгрузить()` і `Загрузить(Текст, ТолькоПроверка)`.

## Встановлення

### 1. Розширення

1. Імпортуйте `exts/mcp1c` у робочу область EDT. У `DT-INF/PROJECT.PMF` замініть `Base-Project: configuration` на ім'я вашого проєкту конфігурації (або вкажіть базовий проєкт у властивостях проєкту). `Runtime-Version: 8.3.23` змініть на версію платформи вашого сервера, якщо вона старша.
2. Завантажте розширення в ІБ з EDT або експортуйте `.cfe` і підключіть його в «Розширеннях конфігурації».
3. Вимкніть для розширення **«Безпечний режим»** і **«Захист від небезпечних дій»**: запит до прикладних даних виконується в привілейованому режимі (модель B, ТЗ п. 7.2), а в безпечному режимі `УстановитьПривилегированныйРежим` ігнорується, і інструменти даних технічного користувача завершуються внутрішньою помилкою «Недостатньо прав для роботи з таблицею ...» (перевірено на BAS ERP 2.5.5). Для вже підключеного розширення — `install_cfe.ps1 -DisableSafeMode` (див. нижче).

Без проєкту в EDT `.cfe` збирається скриптом (Windows, потрібні 1C:EDT і платформа 1С):

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_cfe.ps1        # результат - build\mcp1c.cfe
powershell -ExecutionPolicy Bypass -File tools\install_cfe.ps1 -CheckOnly -Connection 'File="C:\Bases\erp";Usr="Адміністратор";Pwd="";'
powershell -ExecutionPolicy Bypass -File tools\install_cfe.ps1 -Connection 'File="C:\Bases\erp";Usr="Адміністратор";Pwd="";'
```

`build_cfe.ps1` імпортує проєкт у тимчасову робочу область EDT CLI і перевіряє його тими самими перевірками, що EDT з налаштуваннями за замовчуванням (будь-яке зауваження зупиняє збирання, `-NoValidate` — лише показати). Далі вивантажує проєкт у XML, завантажує розширення в тимчасову файлову базу, застосовує його й перед вивантаженням `.cfe` перевіряє конфігурацію платформою (`/CheckConfig`, модулі компілюються в усіх контекстах). `install_cfe.ps1` через зовнішнє з'єднання перевіряє застосовність `.cfe` до конфігурації бази й записує розширення; нове створює з вимкненими безпечним режимом і захистом від небезпечних дій, у наявного змінює лише вміст (з `-DisableSafeMode` — вимикає й ці два прапорці). Якщо версія змінює структуру даних розширення (нові довідники чи реквізити), запис потребує монопольного доступу: закрийте конфігуратор і агент EDT, підключені до бази.

Режим сумісності розширення — 8.3.14 (перевірено на BAS ERP 2.5.5 з режимом сумісності 8.3.14). Вищим за режим сумісності конфігурації він бути не може, тож для конфігурації з нижчим режимом змініть `configurationExtensionCompatibilityMode` у `src/Configuration/Configuration.mdo` на її режим, але не нижче 8.3.11: у режимі 8.3.10 і нижче власні довідники в розширенні не підтримуються, і розширення не застосовується.

### 2. Технічний користувач і публікація

1. Створіть користувача ІБ, наприклад `mcp1c_gateway`: автентифікація 1С, складний пароль, без інтерактивних ролей, роль `mcp1c_Сервис`. Роль дає право «Використання» на методи HTTP-сервісу `mcp1c_Сервер`: без нього платформа відповідає 403 «Недостатньо прав для використання ресурсу з даним HTTP методом» ще до коду сервісу. У конфігураціях на БСП створюйте його штатно через «Користувачі» й додайте роль у профіль групи доступу, інакше БСП може перезаписати ролі (на BAS ERP 2.5.5 користувач, створений напряму в списку користувачів ІБ, теж працює).
2. Зробіть **окрему** публікацію лише для MCP — шаблон [deploy/1c/default.vrd](deploy/1c/default.vrd): без клієнтських застосунків і OData, HTTP-сервіси — тільки `mcp1c_Сервер`, облікові дані технічного користувача — у рядку з'єднання. Атрибути `reuseSessions="autouse"` і `sessionMaxAge="300"` у `<service>` обов'язкові: без `sessionMaxAge` у vrd публікація закриває сеанс пулу через 20 с простою, хоч би що стояло в метаданих HTTP-сервісу, а запит, який потрапляє на сеанс у момент закриття, отримує 500 «Тип не визначений ...» (перевірено на 8.3.27 з IIS 10).

   Заголовок `Authorization` веб-розширення 1С сприймає як облікові дані 1С навіть тоді, коли користувач заданий у рядку з'єднання: запит з `Authorization: Bearer ...` отримує 401 `WWW-Authenticate: Basic` ще до коду сервісу (перевірено на 8.3.27 з IIS 10). Тому до публікації токен приходить у `X-MCP-Authorization`: його туди переносить проксі (п. 3), а в локальній мережі без проксі клієнт передає його сам.

   Файлова база в IIS: задайте для застосунку публікації анонімний вхід від облікового запису пулу (`anonymousAuthentication userName=""`) і дайте цьому обліковому запису права на каталог бази. Від імені IUSR, який IIS бере за замовчуванням, запит до публікації на 8.3.27 з IIS 10 не завершується помилкою, а зависає й займає ядро процесора, доки пул не перезапустять.

   У журналі IIS веб-сервера 1С, як і на проксі, вимкніть поле рядка запиту (`cs-uri-query`): сервер відхиляє токен у рядку запиту, але сам рядок, а з ним і токен, IIS пише в журнал.

3. Ззовні — лише через реверс-проксі з TLS: [deploy/nginx/mcp1c.conf](deploy/nginx/mcp1c.conf) або [deploy/iis/web.config](deploy/iis/web.config). Проксі передає IP клієнта в `X-Real-IP`, обмежує частоту й тіло запиту і відкидає токени в рядку запиту.

Ендпоінт публікації: `http://<веб-сервер>/erp-mcp/hs/mcp1c`, публічний — наприклад, `https://mcp.company.ua/mcp`.

### 3. Увімкнення сервера

Адміністратор (роль `mcp1c_Администратор` або право «Адміністрування») відкриває підсистему **«MCP-сервер» → «Рабочее место MCP-сервера»**, вказує публічну адресу й натискає **«Увімкнути»**, або виконує в контексті сервера:

```bsl
mcp1c_Администрирование.ВключитьСервер("https://mcp.company.ua/mcp");
// IP клієнта береться із заголовка, який ставить проксі; типово X-Real-IP:
// mcp1c_Администрирование.УстановитьЗаголовокАдресаКлиента("X-Forwarded-For");
// без проксі - не довіряти заголовку: УстановитьЗаголовокАдресаКлиента("")
```

Заголовку адреси сервер довіряє, не перевіряючи, звідки прийшов запит. Якщо до публікації 1С можна звернутися в обхід проксі, клієнт поставить у заголовок будь-яку адресу: обійде дозволені адреси клієнта або навмисно заблокує чужу (блокування після 10 невдалих спроб). Тому публікація має бути доступна лише з проксі, а без проксі заголовок задається порожнім: IP у журналі тоді порожній, клієнт із дозволеними адресами отримує відмову, блокування за IP не діє.

Перший автентифікований запит прив'язує сервер до розташування бази (File, Srvr, Ref з рядка з'єднання публікації). Копія бази в іншій ІБ відповідатиме 503, доки не підтвердити перенесення (`ПодтвердитьПереносИнформационнойБазы()`); за замовчуванням це відкликає всі токени.

Інші налаштування: `УстановитьКаноническийАдрес`, `УстановитьРазрешенныеИсточники`, `УстановитьИнструкции`, `УстановитьЗапрещенныеОбъекты`, `УстановитьЗапрещенныеПоля`, `УстановитьСрокХраненияЖурнала`, `ОписаниеНастроек`, `ВыключитьСервер`, `СнятьБлокировкуКлиента`, `СнятьБлокировкуАдреса`. Дані робочого місця — `mcp1c_Мониторинг.ДанныеПанели()`.

### 4. Профіль, клієнт і токен

1. **Профілі доступу**: створіть профіль, наприклад «Продажі — читання». На вкладці *Объекты* додайте `Справочник.Контрагенты`, `Справочник.Номенклатура`, `Документ.РеализацияТоваровУслуг`, `РегистрНакопления.Продажи` з режимом «Чтение»; за потреби — заборони полів і обмеження рядків. Ліміти профілю: 0 — значення за замовчуванням (50 рядків за виклик, 30 викликів за хвилину, 20 000 рядків за добу, 366 днів періоду).
2. **Клієнти доступу**: створіть клієнта, вкажіть профіль і користувача ІБ, права якого будуть верхньою межею (наприклад, менеджера з продажу), за потреби — дозволені IP і вікно часу.
3. На формі клієнта — команда **«Выпустить токен MCP»**: значення токена показується один раз. Відкликання — команда **«Отозвать токен»** на формі токена.

Те саме з коду:

```bsl
Клиент = Справочники.mcp1c_КлиентыДоступа.НайтиПоНаименованию("Claude Code - Андрій");
Выпуск = mcp1c_Администрирование.ВыпуститьТокен(Клиент, 30, "ноутбук");
Сообщить(Выпуск.ФрагментыПодключения); // токен і готові налаштування клієнтів
```

### 5. Підключення клієнтів

Claude Code:

```bash
claude mcp add --transport http onec https://mcp.company.ua/mcp \
  --header "Authorization: Bearer mcp1c_XXXXXXXXXXXX_YYYY"
```

Шаблони для Cursor, VS Code і Claude Desktop (через міст [mcp-remote](https://www.npmjs.com/package/mcp-remote)) — у [deploy/clients](deploy/clients).

Тестова публікація без технічного користувача (1С відповідає 401 з `WWW-Authenticate: Basic`): шаблон [claude-desktop-config.basic-1c.json](deploy/clients/claude-desktop-config.basic-1c.json) — в `Authorization` іде логін 1С, токен — в `X-MCP-Authorization`. `--allow-http` — лише для localhost і локальної мережі. Перевірено з mcp-remote 0.15.2 і IIS 10.

Без проксі (у локальній мережі) передавайте токен у `X-MCP-Authorization: Bearer ...`: заголовок `Authorization` веб-розширення 1С забирає собі (див. «Технічний користувач і публікація»). Шаблони проксі nginx і IIS переносять `Authorization` в `X-MCP-Authorization` самі.

### 6. Перевірка

```bash
python tools/mcp_smoke_test.py --url https://mcp.company.ua/mcp --token mcp1c_...
# об'єкт, що є в базі, але не входить у профіль, має виглядати як відсутній:
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --denied-object Справочник.Пользователи
# тестова публікація без технічного користувача (1С відповідає 401 з WWW-Authenticate: Basic):
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --platform-auth "Користувач:пароль"
# Б4, лише при прямому доступі до публікації: проксі перезаписує X-Real-IP, і тест заблокував би вашу адресу
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --ip-block-test 203.0.113.77
```

З `--platform-auth` облікові дані 1С ідуть в `Authorization: Basic`, а токен — в `X-MCP-Authorization`.

Скрипт перевіряє транспорт і протокол (токен, `Origin`, коди помилок, `server/discover`, сценарій клієнта 2025-11-25), інструменти даних (сторінки й курсор, підроблений курсор, спроби ін'єкції в іменах полів і таблиць, прихований об'єкт, ліміти рядків і періоду, залишки, обороти, зріз), ресурси, промпти й користувацькі інструменти. Перевірки даних беруть об'єкти, дозволені профілем токена, і пропускаються, якщо в базі немає відповідних даних. Код виходу 1 — є помилки. Потрібен лише Python 3.8+.

## Що має підтвердити перевірка на базах

- [x] `Authorization: Bearer` доходить до HTTP-сервісу в публікації без `accessTokenAuthentication`; якщо ні — працює `X-MCP-Authorization`. Перевірено на 8.3.27 з IIS 10: не доходить — навіть в окремій публікації з технічним користувачем у рядку з'єднання веб-розширення 1С відповідає на `Authorization: Bearer` 401 `WWW-Authenticate: Basic`. Токен в `X-MCP-Authorization` працює і в такій публікації (smoke-тест — усі перевірки), і з Basic-автентифікацією 1С; на проксі заголовок переносять шаблони nginx і IIS.
- [ ] Розширення застосовується до трьох конфігурацій з різним режимом сумісності (зафіксувати, які саме). Перевірено: BAS ERP 2.5.5 (режим 8.3.14, платформа 8.3.27, файлова база) — розширення застосовується, інструменти даних працюють на демо-даних (виклик через зовнішнє з'єднання, без HTTP).
- [ ] IP клієнта приходить від проксі (`X-Real-IP`) і видно в журналі викликів. Перевірено без проксі (заголовок ставив тест): адреса потрапляє в журнал викликів, блокування за IP працює; з реальним проксі ще не перевірялося.
- [x] Б4: 10 невдалих спроб з однієї адреси — далі з неї навіть дійсний токен отримує 403 з `Retry-After` на `ipBlockMinutes` (900 с), інші адреси працюють (BAS ERP 2.5.5, `--ip-block-test`).
- [ ] Claude Code і Cursor підключаються й отримують дані в межах профілю; поза профілем — «не знайдено або недоступно».
- [x] Права користувача ІБ клієнта обмежують доступ (об'єкт без права читання недоступний). Перевірено на BAS ERP 2.5.5 через HTTP під технічним користувачем: клієнт, прив'язаний до користувача ІБ з єдиною роллю `ЧтениеКурсовВалют`, бачить з 3719 об'єктів профілю лише `Справочник.Валюты`, `РегистрСведений.КурсыВалют` і перерахування; решта відповідає «не знайдено або недоступний», як відсутній об'єкт. Для звіту перевіряється право «Використання».
- [x] Копія бази в іншій ІБ відповідає 503, доки перенесення не підтверджено. Перевірено на BAS ERP 2.5.5 підміною зафіксованої прив'язки на інше розташування, як у копії: будь-який запит, з токеном і без, отримує 503 з `-32003`, стан сервера показує, що потрібне підтвердження; після `ПодтвердитьПереносИнформационнойБазы(Ложь)` перший запит прив'язує сервер знову, токени лишаються дійсними.
- [ ] Б14: журнали проксі й 1С не містять токенів і секретів. Перевірено: у журналі реєстрації й журналі викликів після тестів немає ні секрету токена, ні пароля технічного користувача. Журнали IIS без прав адміністратора не читаються; до 4838b8d smoke-тест сам передавав справжній токен у рядку запиту (Б3), тож у журналах IIS з полем `cs-uri-query` лишилися відкликані тестові токени.
- [ ] `tools/mcp_smoke_test.py` проходить на всіх трьох базах. Пройдено: BAS ERP 2.5.5 (файлова база, IIS 10, платформа 8.3.27) — усі 40 перевірок етапів 0–2; під технічним користувачем `mcp1c_gateway` з єдиною роллю `mcp1c_Сервис` (модель B, безпечний режим розширення вимкнено) — усі перевірки, крім промптів і користувацьких інструментів, яких у профілі тесту немає.
- [x] Етап 2 на BAS ERP 2.5.5: маски (хеш, часткова, округлення, повна), заборона фільтра й сортування за маскованим полем, режим «тільки агрегати» з мінімальним розміром групи, обмеження рядків з параметром клієнта, ресурси й шаблони ресурсів, промпти з аргументами й `{{today}}`, користувацький інструмент запитом з параметром профілю, пісочниця, аналіз ризиків і звіт про чутливі поля, вивантаження й завантаження налаштувань (перевірка без запису, помилки формату й запиту, «без змін»).

## Розробка

```bash
python tools/check_metadata.py exts/mcp1c
cd tools/bsl-syntax && npm ci && node check.mjs ../../exts/mcp1c/src
```

CI на кожен PR запускає ці перевірки, модульні тести OneScript (`tests/`, модулі чистої логіки з `tests/modules.txt`) і BSL Language Server. Вони ловлять зламаний XML, неузгоджені метадані, виклики неіснуючих або неекспортних методів, синтаксичні помилки й помилки логіки побудови запитів і політик; перевірку проєкту в EDT (зокрема строгу типізацію) вони не замінюють.

Тексти запитів — рядки, тож ні EDT, ні BSL LS не звіряють їх з метаданими (так у запит користувацьких інструментів потрапило неоднозначне поле, яке платформа відхилила під час виконання). На Windows з базою, де встановлено розширення, їх перевіряє платформа — `Запрос.НайтиПараметры()` без виконання запитів:

```powershell
python tools/query_texts.py exts/mcp1c/src --output queries.json
powershell -ExecutionPolicy Bypass -File tools/check_queries.ps1 -Queries queries.json -Connection 'File="C:\Bases\erp";Usr="Адміністратор";Pwd="";'
```

`tools/build_cfe.ps1` додатково перевіряє проєкт EDT CLI (без робочої області EDT — ті самі перевірки, зокрема типів за документуючими коментарями) і компілює модулі розширення платформою в усіх контекстах.
