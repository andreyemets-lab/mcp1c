# mcp1c — MCP-сервер для 1С:Підприємство 8.3

Розширення конфігурації, яке відкриває дані будь-якої бази 1С/BAS для AI-клієнтів (Claude, ChatGPT, Cursor, локальні моделі) за протоколом [Model Context Protocol](https://modelcontextprotocol.io/specification/2026-07-28).

- **Лише читання.** Жодних записів, проведення чи довільного коду: запити будує сервер з канонічних імен метаданих, значення з аргументів ідуть тільки параметрами.
- **Доступ за токеном з терміном дії** і миттєвим відкликанням; OAuth 2.1 для веб-конекторів — на етапі 3.
- **Права за профілем клієнта:** інструменти, об'єкти, поля, обмеження рядків, ліміти обсягу; усе, що не дозволено, заборонено.
- **Універсальність:** без запозичених об'єктів і без залежності від БСП; знання про дані береться з метаданих під час виконання.

Повне технічне завдання: [docs/TZ.md](docs/TZ.md).

## Що вміє сервер

### Протокол

- MCP-ендпоінт на HTTP-сервісі `mcp1c_Сервер` (`/hs/mcp1c`): редакція **2026-07-28** (`server/discover`, заголовки `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, коди `-32020`/`-32022`) і сумісність із клієнтами **2025-11-25 / 2025-06-18** (`initialize`, `ping`).
- Без сесій: кожен запит самодостатній, тож сервер працює з пулом сеансів веб-публікації.

### Інструменти

| Інструмент | Що повертає |
| --- | --- |
| `get_context` | конфігурація, платформа, час і часовий пояс сервера, клієнт, профіль, ліміти |
| `list_objects` | доступні об'єкти метаданих з фільтром за видами й пошуком |
| `describe_object` | реквізити з типами, табличні частини, виміри й ресурси, поля пошуку, придатні інструменти |
| `find_objects` | пошук елементів і документів за рядком у полях пошуку |
| `get_object` | картка об'єкта за посиланням з табличними частинами |
| `query_records` | вибірка з довідника, документа, табличної частини або регістра: фільтри, період, групування, агрегати, сортування |
| `get_balances` | залишки регістра накопичення або бухгалтерії на дату |
| `get_turnovers` | обороти за період, з розбивкою за періодами і залишками |
| `get_slice` | зріз останніх або перших записів періодичного регістра відомостей |

Посилання повертаються як `{"type", "ref", "presentation"}` і так само передаються у фільтри. Дати — місцевий час сервера в ISO 8601 без часового поясу; дата без часу у верхній межі означає кінець дня. Великі вибірки — сторінками з курсором `next_cursor`, підписаним HMAC і прив'язаним до клієнта й аргументів.

### Доступ

- **Клієнт доступу** (`mcp1c_КлиентыДоступа`) — кому видано токени: профіль, користувач ІБ, дозволені IP і `Origin`, вікно часу, власні ліміти (лише менші за профіль), блокування.
- **Профіль доступу** (`mcp1c_ПрофилиДоступа`):
  - *Инструменты* — дозволені інструменти; порожньо — усі 9 інструментів читання;
  - *Объекты* — повне ім'я або шаблон (`Документ.*`, `*`), режим «Чтение» або «Запрещено», політика полів («Все кроме запрещенных» або «Только разрешенные»), обов'язковий фільтр за періодом;
  - *Поля* — дозволи й заборони полів і табличних частин (`Товары`, `Товары.Цена`);
  - *ОграниченияСтрок* — рядки лише з певними значеннями поля: «Равно», «НеРавно», «ВИерархии»; значення — JSON у форматі аргументів, наприклад `{"type": "Справочник.Организации", "ref": "<uuid>"}` або масив таких значень;
  - ліміти: рядків за виклик, викликів за хвилину, рядків за добу, довжина періоду, розмір відповіді, глибина розіменування.
- **Глобальні заборони** в налаштуваннях сервера: шаблони об'єктів і полів (паролі, токени, службові об'єкти розширення), які не відкриє жоден профіль.
- **Права користувача ІБ**, якщо його вказано в клієнті, — верхня межа: об'єкти, які він не може читати, недоступні й клієнту.
- Прихований об'єкт чи поле не відрізняється від відсутнього; посилання на об'єкт, представлення якого клієнту недоступне, показується як `<приховано>`.

### Захист і журнал

- Токени `mcp1c_<id>_<secret>`: у базі лише SHA-256 секрету, відкликання діє з наступного запиту. Токен приймається з `Authorization: Bearer` або `X-MCP-Authorization: Bearer`, у рядку запиту — відхиляється.
- Перевірка `Origin`, ліміт тіла, `Content-Type`, прив'язка до розташування ІБ (копія бази відповідає 503).
- Блокування IP після серії невдалих автентифікацій (типово 10 за 5 хвилин, на 15 хвилин); перевищення частоти — 429 з `Retry-After`, добової квоти — помилка інструмента.
- Тексти з даних очищаються від керуючих і невидимих символів Unicode; довгі рядки обрізаються.
- Журнал викликів `mcp1c_ЖурналВызовов`: клієнт, токен, IP, метод, інструмент, об'єкти, кількість рядків, розмір, результат, причина відмови. Події токенів, безпеки й налаштувань — у журналі реєстрації (`MCP.*`); секрети не пишуться.

## Встановлення

### 1. Розширення

1. Імпортуйте `exts/mcp1c` у робочу область EDT. У `DT-INF/PROJECT.PMF` замініть `Base-Project: configuration` на ім'я вашого проєкту конфігурації (або вкажіть базовий проєкт у властивостях проєкту). `Runtime-Version: 8.3.23` змініть на версію платформи вашого сервера, якщо вона старша.
2. Завантажте розширення в ІБ з EDT або експортуйте `.cfe` і підключіть його в «Розширеннях конфігурації».
3. Вимкніть для розширення **«Безпечний режим»** і **«Захист від небезпечних дій»**: запит до прикладних даних виконується в привілейованому режимі (модель B, ТЗ п. 7.2), а безпечний режим його забороняє.

Режим сумісності розширення — 8.3.14 (перевірено на BAS ERP 2.5.5 з режимом сумісності 8.3.14). Вищим за режим сумісності конфігурації він бути не може, тож для конфігурації з нижчим режимом змініть `configurationExtensionCompatibilityMode` у `src/Configuration/Configuration.mdo` на її режим, але не нижче 8.3.11: у режимі 8.3.10 і нижче власні довідники в розширенні не підтримуються, і розширення не застосовується.

### 2. Технічний користувач і публікація

1. Створіть користувача ІБ, наприклад `mcp1c_gateway`: автентифікація 1С, складний пароль, без інтерактивних ролей, роль `mcp1c_Сервис`. У конфігураціях на БСП створюйте його штатно через «Користувачі» й додайте роль у профіль групи доступу, інакше БСП може перезаписати ролі.
2. Зробіть **окрему** публікацію лише для MCP — шаблон [deploy/1c/default.vrd](deploy/1c/default.vrd): без клієнтських застосунків і OData, HTTP-сервіси — тільки `mcp1c_Сервер`, облікові дані технічного користувача — у рядку з'єднання. Атрибути `reuseSessions="autouse"` і `sessionMaxAge="300"` у `<service>` обов'язкові: без `sessionMaxAge` у vrd публікація закриває сеанс пулу через 20 с простою, хоч би що стояло в метаданих HTTP-сервісу, а запит, який потрапляє на сеанс у момент закриття, отримує 500 «Тип не визначений ...» (перевірено на 8.3.27 з IIS 10).
3. Ззовні — лише через реверс-проксі з TLS: [deploy/nginx/mcp1c.conf](deploy/nginx/mcp1c.conf) або [deploy/iis/web.config](deploy/iis/web.config). Проксі передає IP клієнта в `X-Real-IP`, обмежує частоту й тіло запиту і відкидає токени в рядку запиту.

Ендпоінт публікації: `http://<веб-сервер>/erp-mcp/hs/mcp1c`, публічний — наприклад, `https://mcp.company.ua/mcp`.

### 3. Увімкнення сервера

Адміністратор (роль `mcp1c_Администратор` або право «Адміністрування») відкриває підсистему **«MCP-сервер» → «Состояние MCP-сервера»** і вмикає сервер, або виконує в контексті сервера:

```bsl
mcp1c_Администрирование.ВключитьСервер("https://mcp.company.ua/mcp");
// IP клієнта береться із заголовка, який ставить проксі; типово X-Real-IP:
// mcp1c_Администрирование.УстановитьЗаголовокАдресаКлиента("X-Forwarded-For");
```

Перший автентифікований запит прив'язує сервер до розташування бази (File, Srvr, Ref з рядка з'єднання публікації). Копія бази в іншій ІБ відповідатиме 503, доки не підтвердити перенесення (`ПодтвердитьПереносИнформационнойБазы()`); за замовчуванням це відкликає всі токени.

Інші налаштування: `УстановитьРазрешенныеИсточники`, `УстановитьИнструкции`, `УстановитьЗапрещенныеОбъекты`, `УстановитьЗапрещенныеПоля`, `ОписаниеНастроек`, `ВыключитьСервер`.

### 4. Профіль, клієнт і токен

1. **Профілі доступу**: створіть профіль, наприклад «Продажі — читання». На вкладці *Объекты* додайте `Справочник.Контрагенты`, `Справочник.Номенклатура`, `Документ.РеализацияТоваровУслуг`, `РегистрНакопления.Продажи` з режимом «Чтение»; за потреби — заборони полів і обмеження рядків. Ліміти профілю: 0 — значення за замовчуванням (50 рядків за виклик, 30 викликів за хвилину, 20 000 рядків за добу, 366 днів періоду).
2. **Клієнти доступу**: створіть клієнта, вкажіть профіль і користувача ІБ, права якого будуть верхньою межею (наприклад, менеджера з продажу), за потреби — дозволені IP і вікно часу.
3. На формі клієнта — команда **«Выпустить токен MCP»**: значення токена показується один раз. Відкликання — команда **«Отозвать токен»** на формі токена.

Те саме з коду:

```bsl
Клиент = Справочники.mcp1c_КлиентыДоступа.НайтиПоНаименованию("Claude Code - Андрій");
Выпуск = mcp1c_Администрирование.ВыпуститьТокен(Клиент, 30, "ноутбук");
Сообщить(Выпуск.ФрагментыПодключения); // токен і готові налаштування клієнтів
```

### 5. Підключення клієнтів

Claude Code:

```bash
claude mcp add --transport http onec https://mcp.company.ua/mcp \
  --header "Authorization: Bearer mcp1c_XXXXXXXXXXXX_YYYY"
```

Шаблони для Cursor, VS Code і Claude Desktop (через міст [mcp-remote](https://www.npmjs.com/package/mcp-remote)) — у [deploy/clients](deploy/clients).

Тестова публікація без технічного користувача (1С відповідає 401 з `WWW-Authenticate: Basic`): шаблон [claude-desktop-config.basic-1c.json](deploy/clients/claude-desktop-config.basic-1c.json) — в `Authorization` іде логін 1С, токен — в `X-MCP-Authorization`. `--allow-http` — лише для localhost і локальної мережі. Перевірено з mcp-remote 0.15.2 і IIS 10.

Якщо веб-розширення 1С перехоплює `Authorization: Bearer` і відповідає 401 ще до коду сервісу, передавайте токен у `X-MCP-Authorization: Bearer ...` (або переносьте заголовок на проксі, як у шаблонах nginx і IIS).

### 6. Перевірка

```bash
python tools/mcp_smoke_test.py --url https://mcp.company.ua/mcp --token mcp1c_...
# об'єкт, що є в базі, але не входить у профіль, має виглядати як відсутній:
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --denied-object Справочник.Пользователи
# тестова публікація без технічного користувача (1С відповідає 401 з WWW-Authenticate: Basic):
python tools/mcp_smoke_test.py --url ... --token mcp1c_... --platform-auth "Користувач:пароль"
```

З `--platform-auth` облікові дані 1С ідуть в `Authorization: Basic`, а токен — в `X-MCP-Authorization`.

Скрипт перевіряє транспорт і протокол (токен, `Origin`, коди помилок, `server/discover`, сценарій клієнта 2025-11-25) і інструменти даних: сторінки й курсор, підроблений курсор, спроби ін'єкції в іменах полів і таблиць, прихований об'єкт, ліміти рядків і періоду, залишки, обороти, зріз. Перевірки даних беруть об'єкти, дозволені профілем токена, і пропускаються, якщо в базі немає відповідних даних. Код виходу 1 — є помилки. Потрібен лише Python 3.8+.

## Що має підтвердити перевірка на базах

- [ ] `Authorization: Bearer` доходить до HTTP-сервісу в публікації без `accessTokenAuthentication`; якщо ні — працює `X-MCP-Authorization`. Перевірено: IIS 10 з Basic-автентифікацією 1С — токен в `X-MCP-Authorization` працює; Bearer в `Authorization` ще не перевірявся (потрібна публікація з технічним користувачем у рядку з'єднання).
- [ ] Розширення застосовується до трьох конфігурацій з різним режимом сумісності (зафіксувати, які саме). Перевірено: BAS ERP 2.5.5 (режим 8.3.14, платформа 8.3.27, файлова база) — розширення застосовується, інструменти даних працюють на демо-даних (виклик через зовнішнє з'єднання, без HTTP).
- [ ] IP клієнта приходить від проксі (`X-Real-IP`) і видно в журналі викликів. Без проксі поле IP у журналі порожнє: адреса береться лише із заголовка довіреного проксі.
- [ ] Claude Code і Cursor підключаються й отримують дані в межах профілю; поза профілем — «не знайдено або недоступно».
- [ ] Права користувача ІБ клієнта обмежують доступ (об'єкт без права читання недоступний).
- [ ] Копія бази в іншій ІБ відповідає 503, доки перенесення не підтверджено.
- [ ] `tools/mcp_smoke_test.py` проходить на всіх трьох базах. Пройдено: BAS ERP 2.5.5 (файлова база, IIS 10, платформа 8.3.27) — усі 35 перевірок.

## Розробка

```bash
python tools/check_metadata.py exts/mcp1c
cd tools/bsl-syntax && npm ci && node check.mjs ../../exts/mcp1c/src
```

CI на кожен PR запускає ці перевірки, модульні тести OneScript (`tests/`, модулі чистої логіки з `tests/modules.txt`) і BSL Language Server. Вони ловлять зламаний XML, неузгоджені метадані, виклики неіснуючих або неекспортних методів, синтаксичні помилки й помилки логіки побудови запитів і політик; перевірку проєкту в EDT (зокрема строгу типізацію) вони не замінюють.
